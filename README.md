Как я это реализовал:

Архитектура и ООП: У меня есть главный абстрактный класс, от которого наследуются все игровые сущности. Для свойств (рейтинг, описание) прописал геттеры и сеттеры через @property, чтобы всё было по стандарту. Плюс добавил нужные спецметоды (__str__, __repr__, сравнение через __lt__, проверку равенства и длины), чтобы объекты нормально взаимодействовали между собой и их можно было сортировать по рейтингу.

Свой маппинг: Так как обычные словари (dict) использовать было нельзя, я написал собственный класс-хранилище, который связывает название игры с описанием через списки.

Интерфейс: Сделал окно аккуратным, выровнял все элементы по центру. Чтобы выполнить требование по компонентам, наследовался от стандартных элементов Flet и создал свои 10 классов для кнопок, текстов, полей и списков.

Данные: В программе забито 10 реальных игр. Можно смотреть весь список, включать галочку, чтобы отфильтровать только топ (с рейтингом 9.0+), или вбить название игры в строчку и нажать кнопку, чтобы в статусе вывелось ее подробное описание.

Отчет при выходе: Когда закрываешь приложение, оно само записывает в текстовый файл report.txt отчет с моим логином и точным временем входа и выхода.
